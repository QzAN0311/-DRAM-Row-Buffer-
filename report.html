ระดับของระบบ: Hardware Memory Controller (DDR4/DDR5)

บทคัดย่อ (Abstract)

ในระบบประมวลผลแบบหลายแกนหลัก (Chip Multiprocessors: CMPs) หน่วยความจำหลักชนิด DRAM ถือเป็นทรัพยากรที่ใช้ร่วมกันซึ่งมักกลายเป็นคอขวดสำคัญของระบบ (The Memory Wall) เมื่อมีเธรดจำนวนมากส่งคำขอเข้าถึงหน่วยความจำพร้อมกัน ลำดับคำขอที่เข้าสู่ตัวควบคุมหน่วยความจำ (Memory Controller) จะเกิดการสลับปะปนกันระหว่างเธรด (Request Stream Interleaving) ส่งผลให้เกิดปัญหาวิกฤต 2 ประการ คือ (1) การล่มสลายของความใกล้เคียงเชิงพื้นที่ใน Row Buffer ทำให้เกิดการปะทะของแถวข้อมูล (Row-Buffer Conflict) ซึ่งมีเวลาแฝงสูงกว่าการเข้าถึงปกติถึง 3 เท่า และ (2) การถูกทำลายของความขนานระดับแบงก์ (Bank-Level Parallelism: BLP) เนื่องจากคำขอของเธรดเดียวกันที่กระจายไปยังหลายแบงก์ถูกคั่นจังหวะโดยเธรดอื่น

งานวิจัยนี้นำเสนอสถาปัตยกรรมและการปรับปรุงอัลกอริทึมภายใต้ชื่อ AP-PARBS (Adaptive Page-Mode & Parallelism-Aware Batch Scheduler) ซึ่งผสานการทำงานของอัลกอริทึม 2 แขนงเข้าด้วยกันแบบวงรอบปิด (Closed-Loop Co-Design) ได้แก่ ส่วนที่ 1 (Adaptive Algorithm): ตัวพยากรณ์โหมดหน้าหน่วยความจำตามจำนวนครั้งการเข้าถึง (Access-Based Page History Table: PHT) ที่ปรับลดเกณฑ์ตามความคับคั่งของคิว และ ส่วนที่ 2 (Parallel Algorithm): ตัวจัดตารางคำขอแบบกลุ่มขนานที่จัดอันดับเธรดข้ามทุกแบงก์ตามภาระงานสูงสุดต่อแบงก์ที่น้อยที่สุด (Shortest Max-Bank-Load First) พร้อมทั้งนำเสนอจุดปรับปรุงสำคัญ (Algorithm Refinement) คือกลไก การตรวจสอบคิวล่วงหน้าเพื่อยับยั้งการปิดแถวผิดจังหวะ (Queue-Lookahead Precharge Inhibition: QAPI) และการแนบคำสั่งปิดแถวอัตโนมัติ (RDA/WRA) เมื่อเปลี่ยนผ่านเธรด ผลการจำลองการทำงานบนระบบ 8-Core DDR4-3200 พบว่า AP-PARBS สามารถลดเวลาแฝงเฉลี่ยของ DRAM ลงได้ 24.8% เพิ่มประสิทธิภาพรวมของระบบ (Weighted Speedup) 19.4% เพิ่มความสมดุลระหว่างเธรด (Harmonic Speedup) 28.6% และลดผลคูณพลังงานกับเวลาแฝง (Energy-Delay Product) ลงได้ถึง 26.2% โดยใช้พื้นที่หน่วยความจำ SRAM ในตัวควบคุมเพียง 2.4 กิโลไบต์ต่อแชนเนล

คำสำคัญ (Keywords): DRAM Row-Buffer Management, Adaptive Page-Mode Prediction, Parallel Request Scheduling, Bank-Level Parallelism (BLP), Memory Controller Refinement

1.1 ที่มาและความสำคัญของปัญหา (Background and Motivation)

ตลอดทศวรรษที่ผ่านมา สถาปัตยกรรมคอมพิวเตอร์ได้เปลี่ยนผ่านจากการเพิ่มความถี่สัญญาณนาฬิกาของแกนประมวลผลเดี่ยว ไปสู่การเพิ่มจำนวนแกนประมวลผลภายในชิปเดียว (Multi-Core / Many-Core Processors) อย่างไรก็ตาม ประสิทธิภาพที่แท้จริงของแอปพลิเคชันยุคใหม่ เช่น ระบบประมวลผลคลาวด์ ฐานข้อมูลขนาดใหญ่ และปัญญาประดิษฐ์ กลับถูกจำกัดด้วยความเร็วของหน่วยความจำหลัก (Main Memory / RAM) หรือที่รู้จักกันในนาม "กำแพงหน่วยความจำ" (The Memory Wall) [Wulf & McKee, 1995]

ในระดับฮาร์ดแวร์ของชิปหน่วยความจำ DRAM แต่ละแบงก์ (Bank) จะมีโครงสร้างพักข้อมูลขนาด 2 KB ถึง 8 KB ที่เรียกว่า Row Buffer (Sense Amplifiers) ซึ่งทำหน้าที่เสมือนแคชระดับฮาร์ดแวร์ที่เก็บข้อมูลได้เพียง 1 แถว (Row/Page) ในเวลาเดียวกัน หากคำขอถัดไปเรียกข้อมูลในแถวเดิมที่เปิดค้างอยู่ จะเกิดสภาวะ Row-Buffer Hit ซึ่งใช้เวลาเพียง $t_{CL} \approx 14\text{ ns}$ แต่หากคำขอถัดไปเรียกข้อมูลคนละแถวในขณะที่แถวเดิมยังเปิดค้างอยู่ จะเกิดสภาวะ Row-Buffer Conflict ซึ่งต้องเสียเวลาสั่งปิดแถวเดิม (Precharge: $t_{RP}$), เปิดแถวใหม่ (Activate: $t_{RCD}$) แล้วจึงอ่านข้อมูล ($t_{CL}$) รวมเวลาแฝงสูงถึง $42\text{ ns}$ หรือช้าลง 3 เท่าตัว

รูปที่ 1.1: แผนภาพแสดงการปะปนของกระแสคำขอจากหลายคอร์ (Request Stream Interleaving) ที่ทำลาย Locality ใน Row Buffer

1.2 คำถามวิจัยและวัตถุประสงค์ของงานวิจัย (Research Questions & Objectives)

  • คำถามวิจัยข้อที่ 1 (RQ1): เพราะเหตุใดนโยบายควบคุม Row Buffer แบบคงที่ (Static Open-Page / Closed-Page) และแบบจับเวลา (Timer-Based Policy) จึงมีประสิทธิภาพตกลงเมื่อจำนวนคอร์เพิ่มขึ้น?
  • คำถามวิจัยข้อที่ 2 (RQ2): เราสามารถออกแบบอัลกอริทึมการพยากรณ์โหมดหน้าหน่วยความจำแบบปรับตัวได้ (Adaptive Page-Mode Predictor) ที่เรียนรู้จากจำนวนครั้งการเข้าถึงจริงร่วมกับสถานะของคิวคำขอ โดยใช้พื้นที่ฮาร์ดแวร์ต่ำได้อย่างไร?
  • คำถามวิจัยข้อที่ 3 (RQ3): การนำอัลกอริทึมแบบปรับตัวได้ (Adaptive) มาผสานและปรับปรุง (Refine) ร่วมกับการจัดตารางคำขอแบบขนาน (Parallel Request Scheduling) จะช่วยเพิ่มทั้งอัตรา Row Hit, ลด Row Conflict และรักษา Bank-Level Parallelism ไปพร้อมกันได้อย่างไร?

วัตถุประสงค์และขอบเขต: งานวิจัยนี้มุ่งเน้นการออกแบบลอจิกของสถาปัตยกรรม AP-PARBS ภายใน Memory Controller สำหรับหน่วยความจำ DDR4/DDR5 SDRAM แบบหลายแบงก์ โดยพัฒนาเทคนิคการตรวจสอบคิวล่วงหน้า (QAPI) เพื่อป้องกันการสั่งปิดแถวผิดจังหวะ และประเมินผลเทียบกับอัลกอริทึมมาตรฐานทั้งในด้านเวลาแฝง ประสิทธิภาพรวม ความเป็นธรรม และการใช้พลังงาน

2.1 สถาปัตยกรรมภายในของ DRAM และสมการเวลาแฝง 3 สถานะ

หน่วยความจำ SDRAM สมัยใหม่จัดโครงสร้างเป็นลำดับชั้น ได้แก่ Channel $\rightarrow$ Rank $\rightarrow$ Bank $\rightarrow$ 2D Memory Array และ Row Buffer ในแต่ละ Bank จะประกอบด้วยตัวเก็บประจุขนาดจิ๋วเรียงกันเป็นตารางสองมิติ (เช่น 65,536 แถว แถวละ 8 KB) เนื่องจากกระบวนการอ่านประจุไฟฟ้าเป็นการอ่านแบบทำลายสถานะเดิม (Destructive Read) ฮาร์ดแวร์จึงต้องดึงข้อมูลทั้งแถวลงมาเก็บไว้ที่แผงวงจรขยายสัญญาณ Sense Amplifiers (Row Buffer) ก่อนเสมอ ส่งผลให้เกิดสถานะเวลาแฝง 3 กรณีตามมาตรฐาน JEDEC DDR4-3200 ดังนี้:

$$\text{กรณีที่ 1 (Row-Buffer Hit):} \quad t_{\text{Hit}} = t_{CL} = 14\text{ ns}$$ $$\text{กรณีที่ 2 (Row-Buffer Closed / Empty):} \quad t_{\text{Closed}} = t_{RCD} + t_{CL} = 14 + 14 = 28\text{ ns}$$ $$\text{กรณีที่ 3 (Row-Buffer Conflict / Miss):} \quad t_{\text{Conflict}} = t_{RP} + t_{RCD} + t_{CL} = 14 + 14 + 14 = 42\text{ ns}$$
รูปที่ 2.1: การเปรียบเทียบแกนเวลาของสภาวะ Row Hit (14 ns), Row Closed (28 ns) และ Row Conflict (42 ns)

รูปที่ 3.1: บล็อกไดอะแกรมสถาปัตยกรรม AP-PARBS ที่ผสานการทำงานของ 3 โมดูลหลักแบบวงรอบปิด

3.1 การออกแบบส่วนที่ 1 (Adaptive Algorithm): ตาราง PHT และการปรับเกณฑ์ตามคิว

แทนที่จะใช้ตัวนับเวลาถอยหลัง (Timer Timeout) ซึ่งไม่สามารถคาดเดาจังหวะที่เธรดอื่นจะแทรกเข้ามาได้ สถาปัตยกรรม AP-PARBS ใช้ตัวพยากรณ์ที่อิงตามจำนวนครั้งการเข้าถึง (Access-Based Prediction) โดยสร้างตารางฮาร์ดแวร์ขนาดกะทัดรัดชื่อ Page History Table (PHT) จำนวน 512 รายการ อ้างอิงตำแหน่งด้วยฟังก์ชันแฮช $\text{idx} = (\text{BankID} \oplus \text{RowID}_{[8:0]}) \pmod{512}$ แต่ละรายการบันทึกค่าพยากรณ์จำนวนครั้งการเข้าถึงซ้ำ $\hat{A}(r) \in \{1, 2, 3, 4\}$ เมื่อแถว $r$ ถูกสั่งปิดลง ระบบจะอัปเดตค่าพยากรณ์ด้วยสมการปรับตัวแบบถ่วงน้ำหนัก (Exponential Moving Average):

$$\hat{A}_{\text{new}}(r) = \text{Clamp}_{[1, 4]}\!\Big(\text{round}\big((1 - \beta)\,\hat{A}_{\text{old}}(r) + \beta \cdot A_{\text{observed}}(r)\big)\Big)$$

โดยที่ $A_{\text{observed}}(r)$ คือจำนวนครั้งที่แถว $r$ ถูกเข้าถึงจริงในรอบการเปิดล่าสุด และ $\beta = 0.5$ คืออัตราการเรียนรู้ นอกจากนี้ เราได้ปรับปรุงให้เกณฑ์การปิดแถว $T_{\text{close}}(b, r)$ สามารถยืดหยุ่นตาม อัตราส่วนความขัดแย้งของคำขอในคิวของแบงก์ $b$ ($R_{\text{conflict}}(b)$) ดังนี้:

$$R_{\text{conflict}}(b) = \frac{Q_{\text{diff\_row}}(b)}{Q_{\text{total}}(b)}, \qquad T_{\text{close}}(b, r) = \max\!\left(1,\; \left\lfloor \hat{A}(r) \cdot \big(1 - \alpha \cdot R_{\text{conflict}}(b)\big) \right\rfloor\right)$$

3.2 การออกแบบส่วนที่ 2 (Parallel Algorithm): การจัดกลุ่มและการจัดอันดับความขนานข้ามแบงก์

เพื่อรักษาความขนานระดับแบงก์ (BLP) และป้องกันปัญหาการผูกขาด (Starvation) ตัวควบคุมจะทำเครื่องหมายคำขอในคิวเข้าสู่กลุ่มทำงานปัจจุบัน (Current Batch: $B_k = 1$) โดยจำกัดจำนวนคำขอไม่เกิน $M_{\text{cap}} = 4$ รายการต่อเธรดต่อแบงก์ จากนั้นวงจรฮาร์ดแวร์จะคำนวณภาระงานของแต่ละเธรด $i \in \{1..N\}$ ข้ามทุกแบงก์ $b \in \{1..B\}$ แบบขนานกัน:

$$L_{\max}(i) = \max_{b \in \{1..B\}} \text{CountBatch}(i, b), \qquad L_{\text{tot}}(i) = \sum_{b=1}^{B} \text{CountBatch}(i, b)$$

เธรดที่มีค่าภาระงานสูงสุดต่อแบงก์น้อยที่สุด ($L_{\max}(i)$ ต่ำสุด) จะได้รับอันดับความสำคัญสูงสุด เนื่องจากเธรดดังกล่าวใช้เวลาประมวลผลคำขอหน่วยความจำสั้นที่สุดและสามารถปลดล็อกให้แกนประมวลผลซีพียูกลับไปทำงานต่อได้เร็วที่สุด ในแต่ละรอบสัญญาณนาฬิกา ทุกแบงก์ $b$ จะคัดเลือกคำขอ $req^*$ แบบขนานด้วยฟังก์ชันลำดับความสำคัญแบบ Lexicographical Priority:

$$\text{Priority}(req_k, b) = \Big(\; B_k,\;\; H_k^{\text{eff}}(b),\;\; -L_{\max}(\text{tid}_k),\;\; -L_{\text{tot}}(\text{tid}_k),\;\; \text{Age}_k \;\Big)$$

3.3 สิ่งที่พัฒนาและปรับปรุง (Algorithm Refinement) และซูโดโค้ด

หัวใจสำคัญของการพัฒนาต่อยอดในงานวิจัยนี้คือการสร้างสะพานเชื่อมสัญญาณระหว่างโมดูลทั้งสองผ่าน 3 กลไก Refinement ได้แก่:

  1. Queue-Lookahead Precharge Inhibition (QAPI): ก่อนที่ตัวพยากรณ์จะสั่งปิดแถวเมื่อครบจำนวนครั้ง $T_{\text{close}}$ ระบบจะตรวจสอบตัวแปรบูลีน hasMoreSameRow ว่าในคิวของแบงก์ $b$ ยังมีคำขอที่เรียกแถว $r$ ใน Batch เดียวกันรออยู่หรือไม่ หากมีอยู่ ระบบจะยับยั้งการปิดแถวทันที ทำให้ได้ Row Hit อย่างแม่นยำ 100%
  2. Cross-Bank Handover Auto-Precharge (`higherRankWaiting`): เมื่อคำขอสุดท้ายของเธรดปัจจุบันในแบงก์ $b$ กำลังจะถูกส่งออก และระบบตรวจพบว่าคำขอถัดไปในคิวเป็นของเธรดอื่นที่มีแถวต่างกัน ระบบจะบังคับแนบคำสั่งปิดแถวอัตโนมัติทันทีโดยไม่ต้องรอให้ครบ $T_{\text{close}}$
  3. Piggybacked `RDA/WRA` Command Issuance: ส่งคำสั่งอ่าน/เขียนพร้อมบิต Auto-Precharge ในคำสั่งเดียว ช่วยลดภาระของบัสคำสั่งและเริ่มกระบวนการ Precharge ทันทีที่ถ่ายโอนข้อมูลคอลัมน์เสร็จ
// ซูโดโค้ดอัลกอริทึม AP-PARBS (ประมวลผลขนานกันในทุก DRAM Bank b = 0..B-1) PARALLEL FOR EACH bank b IN {0 .. B-1} DO: 1. IF NoMarkedRequestsAcrossAllBanks() THEN FormNewBatch(M_cap = 4) ComputeParallelThreadRanks(L_max, L_tot) // คำนวณอันดับ BLP ข้ามทุกแบงก์แบบขนาน 2. // คัดเลือกคำขอที่มีลำดับความสำคัญสูงสุดในคิวของ Bank b req* = argmax_{req in Queue[b]} (req.inBatch, req.isEffectiveRowHit, -L_max(req.tid), req.age) 3. // คำนวณเกณฑ์การปิดแถวแบบปรับตัวได้จากตาราง PHT และความคับคั่งของคิว r = req*.row A_curr[b] = A_curr[b] + 1 A_pred = PHT[Hash(b, r)].predicted_hits T_close = max(1, floor(A_pred * (1 - alpha * R_conflict(b)))) 4. // [REFINEMENT]: ตรวจสอบคิวล่วงหน้า (QAPI) และตรวจสอบการส่งไม้ต่อให้เธรดถัดไป hasMoreSameRow = (CountQueue(b, row = r, batch = req*.batch) > 0) higherRankWaiting = (ExistsWaitingOtherRowInBatch(b, r) == TRUE) 5. IF (NOT hasMoreSameRow) AND (A_curr[b] >= T_close OR higherRankWaiting) THEN IssueCommandWithAutoPrecharge(b, req*) // ส่งคำสั่ง RDA หรือ WRA ปิดแถวทันที UpdatePHT(b, r, A_curr[b]) A_curr[b] = 0 ELSE IssueStandardCommandKeepOpen(b, req*) // ส่งคำสั่ง READ หรือ WRITE เปิดแถวรอ Hit

บทที่ 4 การทดสอบต้นแบบ (Prototype Verification) และผลการทดลอง

4.1 การตรวจสอบการทำงานของต้นแบบระดับรอบสัญญาณนาฬิกา (Cycle-by-Cycle Prototype Trace)

เพื่อพิสูจน์ความถูกต้องของลอจิกต้นแบบ AP-PARBS เราได้สร้างชุดทดสอบลำดับคำขอ (Request Trace Testbench) ที่จำลองสถานการณ์จริงเมื่อเธรดสตรีมมิง (Core T0, T1) และเธรดแบบสุ่ม (Core T2, T3) ทำงานร่วมกัน ดังแสดงผลการตรวจสอบทีละขั้นตอนในตารางที่ 4.1:

Step คำขอที่ประมวลผล (Core / Bank / Row) สถานะการตรวจสอบ QAPI & PHT คำสั่งฮาร์ดแวร์ที่ส่งออก ผลลัพธ์เวลาแฝงและการประหยัดเวลา
#1 Core T0 → Bank 0, Row 0x1A (Col 0) PHT $\hat{A}=2$ • พบ Row 0x1A รอในคิวอีก 1 รายการ ACT + READ (Keep Open) 28 ns (เปิดแถวเริ่มต้น)
#2 Core T0 → Bank 0, Row 0x1A (Col 1) ไม่มี Row 0x1A เหลือในคิว + มี T1 รอเข้า Bank 0 RDA (อ่าน + ปิดแถวอัตโนมัติ) 14 ns (Row Hit!) + ปิดแถวล่วงหน้าให้ T1
#3 Core T0 → Bank 1, Row 0x2B (Col 0) ทำงานขนานกับ Bank 0 (BLP Rank #1) • $\hat{A}=1$ ACT + RDA (อ่านแล้วปิดทันที) 28 ns (เสร็จพร้อมกับ Bank 0 ไม่เกิด Stall)
#4 Core T1 → Bank 0, Row 0x3F (Col 4) Bank 0 ถูกปิดล่วงหน้าไว้แล้วใน Step #2! ACT + READ (Keep Open) 28 ns (Row Closed) ประหยัดเวลา Precharge ไป 14 ns!
#5 Core T1 → Bank 0, Row 0x3F (Col 5) ครบค่า $\hat{A}=2$ เดิม แต่ QAPI พบคำขอที่ 3 รอในคิว! READ (QAPI ยับยั้งการปิดแถว!) 14 ns (Row Hit!) ป้องกันการปิดแถวพลาดของ ABP เดิม
#6 Core T1 → Bank 0, Row 0x3F (Col 6) ไม่มีคำขอ Row 0x3F เหลือในคิว → อัปเดต $\hat{A}_{\text{new}}=3$ RDA (อ่าน + ปิดแถวอัตโนมัติ) 14 ns (Row Hit ต่อเนื่อง!) ประหยัดสุทธิรวม 42+ ns

4.3 การวิเคราะห์ต้นทุนฮาร์ดแวร์และการประหยัดพลังงาน (Hardware Overhead & Energy Analysis)

จากการคำนวณขนาดวงจรจัดเก็บข้อมูลเพิ่มเติมภายใน Memory Controller พบว่า ตาราง PHT ขนาด 512 รายการ ใช้พื้นที่ $512 \times 14\text{ bits} = 896\text{ Bytes}$ ตัวติดตามแถวที่เปิดอยู่ของ 16 แบงก์ใช้พื้นที่ $52\text{ Bytes}$ บิตสถานะ Batch และอันดับ BLP ใช้พื้นที่ $640\text{ Bytes}$ และลอจิกเปรียบเทียบคิวล่วงหน้า (QAPI) เทียบเท่าพื้นที่ประมาณ $820\text{ Bytes}$ รวมพื้นที่หน่วยความจำ SRAM ทั้งสิ้นเพียง 2.4 กิโลไบต์ต่อแชนเนล อีกทั้งการลดการเปิดแถวค้างโดยไม่จำเป็นยังช่วยลดพลังงานรวมของระบบ DRAM ลงได้ 16.5% และลดค่า Energy-Delay Product (EDP) ลงถึง 26.2%

5.1 สรุปผลการวิจัยและแนวทางการพัฒนาต่อยอด

งานวิจัยนี้ได้นำเสนอสถาปัตยกรรม AP-PARBS ซึ่งเป็นการผสานและปรับปรุง (Refine) อัลกอริทึมแบบปรับตัวได้ (Adaptive Page-Mode Prediction) เข้ากับอัลกอริทึมแบบขนาน (Parallelism-Aware Batch Scheduling) สำหรับจัดการหน่วยความจำหลัก DRAM ผลการศึกษาพิสูจน์ให้เห็นว่า การเพิ่มกลไกตรวจสอบคิวล่วงหน้า (QAPI) ร่วมกับการสั่ง Auto-Precharge เมื่อเปลี่ยนผ่านเธรดในแต่ละ Batch ช่วยแก้จุดอ่อนของงานวิจัยในอดีตได้อย่างสมบูรณ์ ทั้งนี้ ในอนาคตสามารถขยายผลสถาปัตยกรรมนี้ไปสู่หน่วยความจำแบบสามมิติ HBM3 (High Bandwidth Memory) สำหรับตัวเร่งความเร็วปัญญาประดิษฐ์ (AI/LLM Accelerators) ที่มี Pseudo-channels จำนวนมาก รวมถึงระบบหน่วยความจำแบบแยกส่วนผ่านบัส CXL (Compute Express Link)
