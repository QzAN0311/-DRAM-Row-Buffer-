# AP-PARBS: DRAM Row-Buffer Management

โปรเจกต์นำเสนอแนวคิด **AP-PARBS (Adaptive Page-Mode Prediction integrated with Parallelism-Aware Request Scheduling)** สำหรับจัดการ DRAM Row Buffer ในระบบหลายคอร์ โดยผสานการคาดการณ์การใช้แถวเข้ากับการจัดตารางคำขอหน่วยความจำแบบคำนึงถึงความขนานระหว่าง Bank

ภายในโปรเจกต์มีทั้งสไลด์นำเสนอแบบโต้ตอบ รายงานวิจัย และ Python simulator สำหรับทดลองอัลกอริทึมและรันชุดทดสอบ

## เริ่มใช้งาน

### เปิดสไลด์นำเสนอ

เปิด `index.html` ในเว็บเบราว์เซอร์ หรือรันเว็บเซิร์ฟเวอร์แบบ static จากโฟลเดอร์โปรเจกต์:

```bash
python3 -m http.server 8000
```

จากนั้นเปิด <http://localhost:8000> ในเบราว์เซอร์

การเสิร์ฟผ่าน HTTP แนะนำสำหรับการใช้งานเดโมและการโหลดไฟล์ที่เชื่อมโยงในสไลด์ ส่วนฟอนต์ Noto Sans Thai จะโหลดจาก Google Fonts เมื่อเชื่อมต่ออินเทอร์เน็ตได้

### ใช้งานสไลด์

- `←` / `→` หรือ `Space`: เปลี่ยนสไลด์
- `Home` / `End`: ไปสไลด์แรก / สไลด์สุดท้าย
- `G`: เปิดภาพรวมสไลด์
- `N`: เปิดหรือปิดบทพูดประกอบสไลด์
- `M`: สลับระหว่างโหมดสไลด์กับโหมดอ่านต่อเนื่อง
- `T`: สลับธีมสว่าง/มืด
- `Esc`: ปิดหน้าต่างภาพรวม

นอกจากนี้ยังเลือกสไลด์โดยตรงจากเมนูด้านบนได้ ภายในสไลด์มี Trace Inspector แบบทีละขั้น/เล่นอัตโนมัติ และตัวเปรียบเทียบ workload กับนโยบายจัดตาราง

### รัน Python simulator และชุดทดสอบ

ต้องใช้ Python 3.7 ขึ้นไป โดยไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม:

```bash
python3 ap_parbs_simulator.py
```

สคริปต์จะแสดงผลการจำลองและรัน unit tests จากนั้นเขียน/แทนที่ไฟล์ผลลัพธ์ต่อไปนี้ในโฟลเดอร์ปัจจุบัน:

- `prototype_trace_log.csv`
- `prototype_test_results.json`

หากต้องการรันเฉพาะชุดทดสอบโดยไม่เรียกส่วนรายงานผลของโปรแกรม:

```bash
python3 -m unittest ap_parbs_simulator
```

> **หมายเหตุ:** การจำลองในหน้าเว็บเป็นเดโมเชิงโต้ตอบสำหรับประกอบการนำเสนอ ส่วน `ap_parbs_simulator.py` เป็นตัวจำลองที่สร้าง workload และรันการเปรียบเทียบพร้อมชุดทดสอบ ผลจากสองส่วนนี้จึงมีวัตถุประสงค์และวิธีคำนวณต่างกัน

## แนวคิดที่จำลอง

สำหรับพารามิเตอร์เวลาแฝงที่กำหนดใน simulator:

- **Row hit:** 14 ns
- **Row closed:** 28 ns
- **Row conflict:** 42 ns

AP-PARBS รวมกลไกหลักดังนี้:

1. **Page History Table (PHT):** เรียนรู้จำนวนการเข้าถึงแถวที่คาดว่าจะเกิดซ้ำ
2. **Contention-aware threshold และ QAPI:** ปรับการตัดสินใจปิดแถวตามคำขอที่รออยู่ เพื่อไม่ปิดแถวที่ยังมีคำขอใช้ต่อ
3. **Batching และ BLP ranking:** จัดกลุ่มและเรียงลำดับคำขอโดยคำนึงถึงโหลดของแต่ละ Bank
4. **Auto-precharge:** ใช้การปิดแถวอัตโนมัติเมื่อเหมาะสมกับคำขอถัดไป

ตัวจำลอง Python เปรียบเทียบนโยบาย 6 แบบ ได้แก่ Open-Page FR-FCFS, Closed-Page FCFS, Timer-Based, PAR-BS, ABP ที่ไม่มี QAPI และ AP-PARBS โดยประเมินเวลาแฝง สัดส่วนสถานะ Row Buffer, Weighted/Harmonic Speedup, Max Slowdown, EDP และต้นทุนฮาร์ดแวร์โดยประมาณ

## โครงสร้างการทดลอง

มี workload 4 แบบ ได้แก่ Mixed, Random, Streaming และ Bank-Parallel Burst และมีชุดทดสอบการทำงานแบบ Trace 8 คำขอ, การปรับค่า PHT, QAPI, Batching/BLP ranking และการประมาณพื้นที่ฮาร์ดแวร์
